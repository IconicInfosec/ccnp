📋 Lab Overview

This laboratory exercise focuses on optimizing MAC address table (CAM) management and configuring Switching Database Management (SDM) templates for efficient memory resource allocation. You will learn to manage MAC address aging timers, configure static MAC entries for critical devices, and select appropriate SDM templates for your network requirements.

🎯 Lab Objectives

  • Understand and manage CAM (Content Addressable Memory) table operations
  • Configure MAC address aging timers for optimal network performance
  • Create and maintain static MAC entries for critical devices
  • Monitor and clear dynamic MAC address table entries
  • Understand SDM template architecture and memory allocation
  • Select and configure appropriate SDM templates based on network requirements
  • Optimize TCAM resource allocation for ACLs, QoS, and routing
  • Verify SDM template effectiveness and memory utilization

🏢 Real-World Scenario

ABC Corporation operates a network with critical servers requiring persistent MAC address table entries. The network must support multiple VLANs, extensive ACLs, and QoS policies. You will optimize CAM table management to prevent MAC address exhaustion, configure appropriate SDM templates to maximize TCAM utilization for ACLs, and monitor memory resources to ensure network stability and performance.

Step 1.3: Configure CAM Aging Timer

Change MAC address table aging time from default 300 seconds to 360 seconds

CoreSwitch# configure terminal
CoreSwitch(config)# mac address-table aging-time 360
CoreSwitch(config)# exit

Step 1.4: Verify Aging Timer Configuration

CoreSwitch# show mac address-table aging-time
Global aging time set to: 360 seconds

Step 1.5: Create Static MAC Entry for Critical Server

Add static MAC entry that never ages for a critical server in VLAN 10

CoreSwitch(config)# mac address-table static 0011.2233.4455 vlan 10 interface GigabitEthernet 0/1
CoreSwitch(config)# mac address-table static 00aa.bbcc.ddee vlan 30 interface GigabitEthernet 0/4
CoreSwitch(config)# exit

Step 1.6: Verify Static MAC Entries

Step 1.7: Clear Dynamic MAC Entries (for testing)

CoreSwitch# clear mac address-table dynamic all

ℹ️ Additional clear commands:
clear mac address-table dynamic address 0011.2233.4401
clear mac address-table dynamic interface Gi0/1
clear mac address-table dynamic vlan 10
⚠️ Warning: Clearing MAC entries will cause temporary connectivity disruption as devices relearn. Use only during testing or maintenance windows.

💡 Key Takeaways & Learning Outcomes

  • CAM (Content Addressable Memory) stores MAC address tables for Layer 2 exact-match lookups at high speed
  • MAC address aging (default 300 seconds) ensures stale entries are removed, but can be adjusted for specific network conditions
  • Static MAC entries never age and are useful for critical servers and appliances requiring persistent forwarding paths
  • SDM (Switching Database Management) templates optimize TCAM allocation for specific network functions
  • TCAM (Ternary Content Addressable Memory) stores ACLs, QoS policies, and routing information
  • SDM template changes require switch reload to take effect - plan carefully in production networks
  • Different templates provide different trade-offs: Access optimizes for ACLs, Routing for Layer 3, VLAN for broadcast domains
  • TCAM exhaustion can prevent new ACLs or routes from being installed - proper template selection is critical

🏆 Best Practices & Security Recommendations

CAM Management Best Practices

  • Monitor CAM table utilization regularly to prevent overflow
  • Adjust aging timers based on network stability and device mobility patterns
  • Use static MAC entries for critical servers and network appliances
  • Implement port security to limit MAC addresses per port, preventing CAM exhaustion
  • Regularly clear dynamic entries for testing but avoid excessive clearing in production

SDM Template Best Practices

  • Right-size SDM templates for your network requirements to avoid TCAM exhaustion
  • Monitor TCAM utilization and plan template changes before hitting capacity limits
  • Test SDM template changes in lab before production deployment
  • Schedule template changes during maintenance windows requiring switch reload
  • Consolidate and optimize ACLs to reduce TCAM entry consumption

🔧 Troubleshooting Guide

Issue Cause Solution
CAM table fills to capacity Excessive MAC learning or spoofing Clear entries, enable port security, adjust aging timer
Static MAC not appearing in table Incorrect VLAN or interface specification Verify VLAN exists, check interface name, re-enter command
TCAM exhaustion error Current template insufficient for ACLs Switch to Access template, reload switch
Switch won't reload after template change Configuration not saved before reload Save running-config, then perform reload
