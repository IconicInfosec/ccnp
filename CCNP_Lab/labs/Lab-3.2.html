📋 Lab Overview

This laboratory exercise focuses on configuring trunk ports and implementing VLAN tagging across multiple switches in a datacenter environment. You will establish secure trunk links between switches, configure allowed VLANs, manage native VLAN assignments, and understand VLAN propagation across the network infrastructure.

🎯 Lab Objectives

  • Configure trunk ports between switches using Dynamic Trunking Protocol (DTP)
  • Understand 802.1Q VLAN tagging standards and frame structure
  • Configure allowed VLANs on trunk links using switchport trunk allowed vlan commands
  • Manage native VLAN configuration to prevent VLAN tagging mismatches
  • Verify trunk port configuration and VLAN propagation across switches
  • Identify and mitigate VLAN hopping vulnerabilities
  • Implement Layer 2 security best practices for trunk links
  • Troubleshoot inter-switch VLAN connectivity issues

🏢 Real-World Scenario

ABC operates a multi-floor datacenter with servers and resources distributed across two physical floors. Each floor has independent Cisco Catalyst switches (Floor1-SW1 and Floor2-SW2), and they must communicate while maintaining VLAN segmentation. You will configure trunk ports using 802.1Q tagging to extend VLANs across switch interconnects, properly configure native VLANs, and demonstrate secure inter-switch communication while preventing VLAN hopping attacks.

2Configure Trunk Ports on Both Switches

Step 2.1: Configure Trunk Port on Floor1-SW1 (Gi0/24)

Floor1-SW1(config)# interface GigabitEthernet 0/24
Floor1-SW1(config-if)# switchport mode trunk
Floor1-SW1(config-if)# description Trunk-Link-Floor1-to-Floor2
Floor1-SW1(config-if)# exit

Step 2.2: Configure Trunk Port on Floor2-SW2 (Gi0/24)

Floor2-SW2(config)# interface GigabitEthernet 0/24
Floor2-SW2(config-if)# switchport mode trunk
Floor2-SW2(config-if)# description Trunk-Link-Floor2-to-Floor1
Floor2-SW2(config-if)# exit
⚠️ Important: By default, DTP (Dynamic Trunking Protocol) will automatically negotiate the trunk if one side is set to trunk mode. For security, disable DTP and use "switchport nonegotiate" in production environments.

3Configure Allowed VLANs on Trunk Links

Step 3.1: Configure Allowed VLANs on Floor1-SW1 Trunk (Gi0/24)

Floor1-SW1(config)# interface GigabitEthernet 0/24
Floor1-SW1(config-if)# switchport trunk allowed vlan 10,20,30
Floor1-SW1(config-if)# exit

Step 3.2: Configure Allowed VLANs on Floor2-SW2 Trunk (Gi0/24)

Floor2-SW2(config)# interface GigabitEthernet 0/24
Floor2-SW2(config-if)# switchport trunk allowed vlan 10,20,30
Floor2-SW2(config-if)# exit

4Configure Native VLAN on Trunk Links

Step 4.1: Set Native VLAN to 99 on Floor1-SW1 Trunk

Floor1-SW1(config)# interface GigabitEthernet 0/24
Floor1-SW1(config-if)# switchport trunk native vlan 99
Floor1-SW1(config-if)# exit

Step 4.2: Set Native VLAN to 99 on Floor2-SW2 Trunk

Floor2-SW2(config)# interface GigabitEthernet 0/24
Floor2-SW2(config-if)# switchport trunk native vlan 99
Floor2-SW2(config-if)# exit
✓ Security Best Practice: By using VLAN 99 (Management) as the native VLAN instead of VLAN 1, we prevent unauthorized access through the default VLAN.

5Disable DTP and Enable Nonegotiate (Security Best Practice)

Step 5.1: Disable DTP on Floor1-SW1 Trunk (Gi0/24)

Floor1-SW1(config)# interface GigabitEthernet 0/24
Floor1-SW1(config-if)# switchport nonegotiate
Floor1-SW1(config-if)# exit

Step 5.2: Disable DTP on Floor2-SW2 Trunk (Gi0/24)

Floor2-SW2(config)# interface GigabitEthernet 0/24
Floor2-SW2(config-if)# switchport nonegotiate
Floor2-SW2(config-if)# exit

Step 6.1: Save Floor1-SW1 Configuration

💡 Key Takeaways & Learning Outcomes

  • Trunk ports carry multiple VLANs using 802.1Q tagging, enabling inter-switch communication
  • Native VLAN is the untagged VLAN on a trunk link and must match on both endpoints
  • Allowed VLANs should be explicitly restricted on trunk links to prevent unauthorized VLAN propagation
  • DTP should be disabled in production environments to prevent VLAN hopping attacks
  • MAC address learning occurs across trunk links, enabling inter-switch communication within the same VLAN
  • Mismatched native VLANs create security vulnerabilities and should be immediately corrected
  • Using a dedicated management VLAN (instead of VLAN 1) as the native VLAN improves Layer 2 security

🏆 Best Practices & Security Recommendations

Trunk Port Configuration Best Practices

  • Always explicitly configure switchport mode trunk instead of relying on DTP negotiation
  • Disable DTP with switchport nonegotiate to prevent DTP attacks
  • Restrict allowed VLANs to only those required for the link, not "all"
  • Configure native VLAN explicitly and verify it matches on both trunk endpoints
  • Use a dedicated management VLAN (e.g., VLAN 99) instead of VLAN 1 for the native VLAN
  • Document trunk links, allowed VLANs, and native VLAN in network diagrams
  • Use consistent naming conventions for trunk port descriptions

VLAN Hopping Prevention

  • Never use VLAN 1 as native VLAN; create dedicated management VLAN (e.g., VLAN 99)
  • Disable DTP to prevent double-tagged VLAN hopping attacks
  • Ensure native VLANs match on both trunk ends
  • Restrict access ports to specific VLANs with proper port security
  • Regularly audit VLAN and trunk configurations for security gaps

🔧 Troubleshooting Guide

Issue Cause Solution
Trunk link not establishing Trunk mode not enabled or port modes mismatch Verify both ends: show interfaces trunk
VLAN not propagating across trunk VLAN not in allowed list or native VLAN mismatch Verify allowed VLANs and native VLAN on both switches
Cross-floor devices cannot communicate Different VLAN assignments or trunk not configured Verify VLAN membership and ping test
MAC addresses not learned across trunk Trunk link down or VLAN not allowed Check trunk status and MAC address table
