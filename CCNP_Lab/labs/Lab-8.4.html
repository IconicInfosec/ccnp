🔒 Lab 8.4: Private VLAN (PVLAN) Port Isolation

Cisco CCNP 350-401 (ENCOR) & CCNP 300-410 (ENARSI) Enterprise Networking

Duration: 60-75 minutes | Difficulty: Intermediate-Advanced | Version: 1.0

🔒 Protected

📋 Lab Overview & Objectives

Lab Objective: Master Private VLAN (PVLAN) configuration for Layer 2 network segmentation and port isolation. Implement PVLAN port types (promiscuous, community, isolated) and communication rules to segregate devices within the same IP subnet for enhanced security and traffic control .

🎯 Learning Outcomes

  • Configure VTP transparent mode (prerequisite for PVLAN)
  • Create Primary, Community, and Isolated VLANs
  • Configure PVLAN port types (promiscuous, host, trunk)
  • Understand PVLAN communication rules and restrictions
  • Implement port isolation for multi-tenant environments
  • Verify PVLAN configuration and port associations
  • Troubleshoot PVLAN communication issues
  • Compare PVLAN with standard VLANs

Key PVLAN Concepts

Component Description Lab Function
Primary VLAN Main VLAN containing all PVLAN ports VLAN 100 (Primary)
Community VLAN Secondary VLAN where member ports communicate VLAN 200, 300 (Community)
Isolated VLAN Secondary VLAN with NO inter-port communication VLAN 400 (Isolated)
Promiscuous Port Connects to router/gateway, communicates with all VLANs Gi0/1 (Gateway)
Host Port Isolated or community member, connects to end devices Gi0/2-0/5 (Clients)

🔗 PVLAN Communication Rules

✅ Allowed Communications :
  • Promiscuous Port ↔ Community Ports (bidirectional)
  • Promiscuous Port ↔ Isolated Ports (bidirectional)
  • Community Ports ↔ Community Ports (within same community only)
❌ Blocked Communications :
  • Isolated Ports ↔ Isolated Ports (NO communication)
  • Community Ports ↔ Isolated Ports (NO communication)
  • Different Community VLANs ↔ Each other (isolated)

📋 PVLAN Configuration Prerequisites

⚠️ Important: VTP Must Be Transparent
  • VTP must be configured in Transparent Mode before creating PVLANs
  • VTP transparent mode allows independent VLAN management on each switch
  • Private VLANs cannot be created while VTP is in server or client mode

⚙️ Step-by-Step Configuration Guide

STEP 1: Configure VTP Transparent Mode (Prerequisite)

Switch# configure terminal Switch(config)# vtp mode transparent ! Switch(config)# vtp domain pvlan-domain ! Switch(config)# end Switch# show vtp status
Explanation :
  • vtp mode transparent - Allows independent VLAN management
  • vtp domain pvlan-domain - Sets VTP domain name
  • Transparent mode is REQUIRED for PVLAN configuration

STEP 2: Create Primary VLAN

Switch# configure terminal ! Switch(config)# vlan 100 Switch(config-vlan)# name Primary-VLAN Switch(config-vlan)# private-vlan primary Switch(config-vlan)# end ! ! Verify Switch# show vlan private-vlan
Key Command :
  • private-vlan primary - Designates VLAN 100 as primary PVLAN

STEP 3: Create Community VLANs

Switch# configure terminal ! Switch(config)# vlan 200 Switch(config-vlan)# name Community-VLAN-A Switch(config-vlan)# private-vlan community Switch(config-vlan)# exit ! Switch(config)# vlan 300 Switch(config-vlan)# name Community-VLAN-B Switch(config-vlan)# private-vlan community Switch(config-vlan)# end ! ! Verify Switch# show vlan private-vlan type
Key Command :
  • private-vlan community - Designates VLANs 200 & 300 as community PVLANs

STEP 4: Create Isolated VLAN

Switch# configure terminal ! Switch(config)# vlan 400 Switch(config-vlan)# name Isolated-VLAN Switch(config-vlan)# private-vlan isolated Switch(config-vlan)# end ! ! Verify Switch# show vlan private-vlan type
Key Command :
  • private-vlan isolated - Designates VLAN 400 as isolated PVLAN

STEP 5: Associate Secondary VLANs with Primary VLAN

Switch# configure terminal ! Switch(config)# vlan 100 Switch(config-vlan)# private-vlan association 200,300,400 ! ! Associate individual secondary VLANs Switch(config)# vlan 200 Switch(config-vlan)# private-vlan association 100 ! Switch(config)# vlan 300 Switch(config-vlan)# private-vlan association 100 ! Switch(config)# vlan 400 Switch(config-vlan)# private-vlan association 100 Switch(config-vlan)# end ! ! Verify association Switch# show vlan private-vlan association
Explanation :
  • private-vlan association - Links community & isolated VLANs to primary
  • Must be done for each VLAN pair

STEP 6: Configure Promiscuous Port (Gateway)

Switch# configure terminal ! Switch(config)# interface GigabitEthernet0/1 Switch(config-if)# description Gateway/Router Connection Switch(config-if)# switchport mode private-vlan promiscuous Switch(config-if)# switchport private-vlan mapping 100 200,300,400 Switch(config-if)# no shutdown Switch(config-if)# end ! ! Verify Switch# show interface GigabitEthernet0/1 switchport private-vlan
Key Commands :
  • switchport mode private-vlan promiscuous - Enables promiscuous port
  • switchport private-vlan mapping 100 200,300,400 - Maps secondary VLANs

STEP 7: Configure Community Host Ports

Switch# configure terminal ! ! Gi0/2 - Community A member Switch(config)# interface GigabitEthernet0/2 Switch(config-if)# description Client-Community-A Switch(config-if)# switchport mode private-vlan host Switch(config-if)# switchport private-vlan host-association 100 200 Switch(config-if)# no shutdown ! ! Gi0/3 - Community A member Switch(config)# interface GigabitEthernet0/3 Switch(config-if)# description Client-Community-A-2 Switch(config-if)# switchport mode private-vlan host Switch(config-if)# switchport private-vlan host-association 100 200 Switch(config-if)# no shutdown ! ! Gi0/4 - Community B member Switch(config)# interface GigabitEthernet0/4 Switch(config-if)# description Client-Community-B Switch(config-if)# switchport mode private-vlan host Switch(config-if)# switchport private-vlan host-association 100 300 Switch(config-if)# no shutdown Switch(config-if)# end
Key Commands :
  • switchport mode private-vlan host - Configures host port
  • switchport private-vlan host-association 100 200 - Associates with primary & secondary VLAN

STEP 8: Configure Isolated Host Port

Switch# configure terminal ! ! Gi0/5 - Isolated VLAN member Switch(config)# interface GigabitEthernet0/5 Switch(config-if)# description Client-Isolated Switch(config-if)# switchport mode private-vlan host Switch(config-if)# switchport private-vlan host-association 100 400 Switch(config-if)# no shutdown Switch(config-if)# end ! ! Verify all port associations Switch# show vlan private-vlan

🔄 Communication Testing Scenarios

Scenario 1: Community A Internal Communication (Allowed)

Test: Ping from Client Gi0/2 (Community A) to Client Gi0/3 (Community A)
Client2> ping 192.168.1.3 Pinging 192.168.1.3 with 32 bytes of data: Reply from 192.168.1.3: bytes=32 time=1ms TTL=255 Reply from 192.168.1.3: bytes=32 time=1ms TTL=255 ... Ping statistics: Sent=4, Received=4, Lost=0 (0% loss)
✅ EXPECTED: Ping successful (same community can communicate)

Scenario 2: Community A to Community B (Blocked)

Test: Ping from Client Gi0/2 (Community A) to Client Gi0/4 (Community B)
Client2> ping 192.168.1.4 Pinging 192.168.1.4 with 32 bytes of data: General failure. (Request timed out.) General failure. (Request timed out.)
✅ EXPECTED: Ping fails (different communities cannot communicate)

Scenario 3: Isolated Port Communication (Completely Blocked)

Test: Ping from any client to Gi0/5 (Isolated)
Client2> ping 192.168.1.5 Pinging 192.168.1.5 with 32 bytes of data: General failure. (Request timed out.) General failure. (Request timed out.)
✅ EXPECTED: Ping fails (isolated ports block all host-to-host communication)

Test: Ping from any client to Router via promiscuous port

✅ EXPECTED: Ping successful (all clients can reach promiscuous port/router)

🐛 Troubleshooting Guide

Issue 1: Cannot Create Private VLANs (VTP Mode Error)

Symptoms: "private-vlan command fails" or VLAN creation blocked
Solutions :
  • Verify VTP mode is transparent: show vtp status
  • Change to transparent if needed: vtp mode transparent
  • Cannot create PVLAN in server or client mode
  • Wait 30 seconds after changing VTP mode

Issue 2: Hosts Cannot Communicate Within Same Community

Symptoms: Ping fails between hosts in same community VLAN
Solutions :
  • Verify both ports are in same community VLAN: show interface switchport private-vlan
  • Ensure ports are in "host" mode, not promiscuous
  • Check secondary VLAN is associated with primary
  • Verify no additional VLAN configuration on ports

Issue 3: Secondary VLAN Not Associating with Primary

Symptoms: Association command fails or shows error
Solutions :
  • Verify both VLANs exist: show vlan private-vlan type
  • Primary must be created first
  • Secondary VLAN must be community or isolated, not primary
  • Use correct command syntax for associations

Issue 4: Promiscuous Port Not Mapping Secondary VLANs

Symptoms: Router cannot reach isolated clients
Solutions :
  • Verify port is in promiscuous mode: show interface Gi0/1 switchport private-vlan
  • Check mapping includes all secondary VLANs
  • Remapped if adding new secondary VLAN
  • Example: switchport private-vlan mapping 100 200,300,400

Issue 5: Isolated Ports Communicating (Should Be Blocked)

Symptoms: Hosts in isolated VLAN can see each other
Solutions :
  • Verify secondary VLAN type is "isolated": show vlan private-vlan type
  • Isolated type must be used, not community
  • If needed, change: delete VLAN and recreate as isolated
  • Multiple isolated VLANs can be associated with one primary

📊 PVLAN vs Standard VLAN Comparison

Feature Private VLAN Standard VLAN
Port Isolation All ports isolated unless same community All ports in VLAN can communicate
IP Address Usage Multiple devices share one subnet One IP subnet per VLAN
Scalability More scalable (saves IP addresses) Limited by IP subnets
Configuration Complex (promiscuous, host ports) Simple (standard VLANs)
Security Enhanced (port isolation prevents communication) Limited (VLAN-based only)
Use Case Device isolation, guest networks, multi-tenant Department/team segregation
